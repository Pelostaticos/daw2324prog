## 📝 Introducción al Flujo del Módulo

Este documento presenta un resumen analítico del Módulo de Programación del curso 2023/2024, centrado en el desarrollo de la lógica algorítmica y la aplicación práctica de la Programación Orientada a Objetos (POO) en Java. El recorrido se inició con la comprensión de la sintaxis fundamental (variables, tipos de datos y operadores) para luego estructurar el flujo de ejecución mediante condicionales y bucles. La fase inicial culminó con la implementación de lógica compleja para sistemas como una Máquina Expendedora y la simulación de Formaciones Romanas, sentando las bases sólidas para la abstracción de sistemas y el uso eficiente del depurador del IDE.

## 📌 Tarea 1: Asentando las Bases de la Programación.

La Tarea Online 01 del módulo de Programación ha sido el punto de partida, actuando como la piedra angular para asentar los conceptos esenciales de la ingeniería de software. El objetivo de esta tarea fue familiarizarse con la estructura canónica de un programa Java, la creación y gestión de paquetes, y el manejo fundamental de los tipos de datos y operadores. Desde el cálculo del volumen de un cilindro hasta la simulación de la gestión de recursos hídricos o las reglas de un parque acuático, cada ejercicio exigió la aplicación rigurosa de variables, constantes y estructuras condicionales (if-else). Esta tarea inicial fue crucial para desarrollar la disciplina de sintaxis y la lógica algorítmica necesarias para abordar la programación orientada a objetos en las unidades posteriores.


## 📌 Tarea 2 sobre el uso de estructuras de control de flujo.

Esta etapa del módulo se centró en dominar los Nadis de Control de Flujo esenciales. La Tarea PROG02 fue una inmersión completa en el manejo del Tamas (la lógica de selección con if/switch) y el Rajas (la repetición controlada con bucles). El objetivo final no es solo escribir código, sino dirigir su ejecución con precisión, utilizando además las herramientas de depuración para garantizar el Sattva (la funcionalidad libre de errores) en proyectos como la simulación de una máquina expendedora y un desafío de formación militar.

<u>Contenidos Clave de PROG02</u> Esta tarea consolidó la escritura y depuración de código utilizando:

* Estructuras de Selección: Uso avanzado de if-else if-else y switch para la toma de decisiones complejas.
* Estructuras de Repetición: Implementación de for, while y do-while para tareas iterativas.
* Sentencias de Salto: Aplicación de break y continue para modificar el flujo normal de los bucles.
* Depuración: Uso efectivo del depurador del IDE para localizar fallos en la ejecución de la lógica del programa.

## 📌 Tarea 3 sobre Trabajando con clases, objetos y métodos.

Esta etapa del módulo se centró en dominar los Nadis de Datos a través de la Programación Orientada a Objetos (POO). La Tarea PROG03 fue una inmersión completa en el manejo del Tamas que supone la complejidad del mundo real, resolviéndola mediante la abstracción en Clases y Objetos. 

El objetivo no es solo la funcionalidad, sino la correcta representación del mundo real, utilizando Constructores para inicializar el Rajas de las variables, y Métodos para canalizar las acciones. La depuración se orientó a garantizar el Sattva (la funcionalidad libre de errores) en proyectos como la simulación de reservas de teatro, lanzamientos de dados y cálculos de fechas.

<u>Contenidos Clave de PROG03</u>

* Esta tarea consolidó la escritura y depuración de código utilizando:
Clases y Objetos: Creación de plantillas (clases) y entidades (objetos) para representar conceptos del problema.
  * Constructores: Uso de constructores por defecto y parametrizados para la correcta inicialización de objetos.
  * Métodos y Propiedades (Getters/Setters): Definición de métodos para consultar y modificar el estado interno de los objetos.
  * Librerías de Objetos: Incorporación de librerías externas (ej. java.util.Random, java.time) para extender la funcionalidad del programa.
  * Manejo de Excepciones: Introducción a la gestión básica de errores mediante la propagación (aunque no el tratamiento completo).

## 📌 Tarea-4: Utilizando cadenas de caracteres y arrays.

Esta tarea marca la transición del manejo de tipos de datos simples a estructuras de datos complejas y de longitud fija. El enfoque se centra en dos pilares: la manipulación avanzada de la clase String de Java y el dominio en la declaración, inicialización y procesamiento eficiente de arrays (unidimensionales y bidimensionales). Los ejercicios requieren la implementación de algoritmos de recorrido, búsqueda y, crucialmente, la utilización de expresiones regulares para la validación de patrones en cadenas de texto, como se aplica en la comprobación del Nivel de Seguridad de Contraseñas.

## 📌 Tarea-5: Desarrollo de clases.

Esta etapa representa un camino fundamental, profundizando en la Programación Orientada a Objetos (POO) a través de la construcción integral de una clase, probablemente un modelo de Aeronave. El enfoque se ha movido desde el uso básico de clases (Tarea 3) a la arquitectura completa, donde se practican todos los principios de la Encapsulación y el ciclo de vida del objeto.

Se trabajan exhaustivamente los Constructores y el Método de Fábrica para la inicialización controlada. Los métodos (getters y setters) actúan como filtros contra los datos erróneos, asegurando la integridad del estado. Además, se incluye la documentación con Javadoc, que representa el equilibrio del código, garantizando la claridad y mantenibilidad.

## 📌 Tarea-6: Utilización avanzada de clases.

Esta tarea abre la vía hacia la arquitectura compleja de sistemas. El enfoque pasa de la clase individual a la Jerarquía de Clases mediante la implementación de un modelo de negocio. Por ejemplo, un catálogo de Mobiliario Modular.

Se practica la Herencia (Mueble -> Asiento, Almacenaje), fundamental para evitar el error de la duplicidad de código. Se dominan las Clases Abstractas y las Interfaces (Ajustable, Personalizable), que imponen un contrato a las clases derivadas y permiten la aplicación rigurosa del Polimorfismo.

El objetivo es alcanzar el equilibrio del diseño, donde cada objeto no solo se comporta correctamente, sino que se integra de manera limpia en una estructura mayor y coherente.

## 📌 Tarea-7: Manejos de estructuras de datos internas.

Esta etapa supone la apertura de una puerta fundamental: La gestión eficiente de la información dentro de la memoria. Se pasa de manipular objetos individuales a colecciones de objetos.

El objetivo es dominar el API de Colecciones de Java, seleccionando la estructura más adecuada (Lista, Conjunto o Mapa) para cada necesidad, lo cual evita el error del código ineficiente. 

Se trabaja intensamente con ArrayList, HashSet y HashMap para tareas de almacenamiento, búsqueda y clasificación. Por ejemplo, con las especies en un Jardín Botánico.

El uso de Genéricos asegura la pureza del tipo de dato, manteniendo el Sattva del sistema y su robustez. El Rajas (la acción) se centra en implementar métodos de negocio que manipulan eficientemente estas estructuras.

## 📌 Tarea-8: Estructuras de datos externas. Los ficheros.

Esta etapa estableció la persistencia del programa, utilizando los canales de Entrada/Salida (I/O). El objetivo fue asegurar que el estado (la coherencia de los objetos en memoria) no se pierda al finalizar la ejecución, sino que se transfiera al disco. La ejecución se manifestó en la correcta implementación de tres mecanismos de persistencia: Texto plano, Serialización binaria y Ficheros XML.

Fue crucial gestionar correctamente las excepciones de I/O (el fallo del disco/sistema) y cerrar todos los recursos (streams) utilizando bloques try-with-resources.

## 📌 Tarea-9: Aplicaciones gráficas de escritorio. Juego de Memoria.

Esta etapa supone la implementación de la Interacción y Presentación Visual, migrando las aplicaciones desde la consola (Entrada/Salida de texto) a una Interfaz Gráfica de Usuario (GUI). El proyecto principal es el desarrollo del Juego Memorízame (Memory Game).

El desafío principal es aplicar el patrón Modelo-Vista-Controlador (MVC), donde:

    • Vista (Coherencia Visual): La interfaz gráfica (el tablero, las cartas) debe ser coherente, intuitiva y visualmente estilizada (uso de CSS/estilos para la estética).
    • Modelo: La lógica de datos (el estado del tablero, las parejas encontradas).
    • Controlador (Lógica de Eventos): La implementación de los manejadores de eventos (ActionEvent) que traducen la acción del usuario (clic en una carta) a una acción en la lógica del juego (voltear la carta, comprobar pareja).

La Lógica del Controlador se enfoca en la implementación para gestionar el flujo del juego: mezcla inicial, gestión del turno (dos clics), comprobación de la coincidencia y bloqueo temporal de la interfaz para evitar errores por concurrencia o múltiples clics.

## 📌 Tarea-10: Operaciones CRUD sobre una base de datos H2.

Esta tarea finaliza el ciclo de persistencia, implementando el mecanismo de Conexión (JDBC) para interactuar con bases de datos. El objetivo principal es garantizar que la información se gestione de manera estructurada y consistente, manteniendo la integridad de los datos.

Se domina el patrón CRUD (Crear, Leer, Actualizar, Borrar) a través de la interfaz JDBC, empleando un motor de base de datos relacional ligero como H2. Los conceptos clave son:

    1. Conexión: Establecer y cerrar correctamente el enlace/recurso de conexión a la base de datos (usando try-with-resources).
    2. Operaciones DDL: Crear la estructura de tablas (CREATE TABLE), definiendo claves primarias y foráneas para imponer la restricción/integridad de las relaciones.
    3. Operaciones DML (CRUD):
        ◦ Crear (C): Sentencias INSERT (carga inicial de datos).
        ◦ Leer (R): Sentencias SELECT para recuperar datos complejos (ej. joins para obtener películas y sus plataformas).
        ◦ Actualizar (U): Sentencias UPDATE para modificar datos (ej. cambiar el nombre de una plataforma).
        ◦ Borrar (D): Sentencias DELETE para eliminar registros (ej. borrar una plataforma).
    4. Base de Datos OO: Se requiere también el análisis conceptual de las Bases de Datos Orientadas a Objetos como alternativa a la persistencia relacional.

Es fundamental utilizar Sentencias Preparadas (PreparedStatement) para la ejecución eficiente y segura de las consultas, mitigando los riesgos de inyección SQL.

## 💡 Conclusión y Hoja de Ruta.

La competencia principal adquirida en esta etapa reside en la aplicación rigurosa de la Programación Orientada a Objetos (POO), permitiendo la organización del código en clases y objetos coherentes que modelan entidades reales (Teatros, Dados, Fechas, Aeronaves, Muebles, Plantas). Este dominio se complementa con la habilidad de depuración para garantizar la funcionalidad y estabilidad del código.
